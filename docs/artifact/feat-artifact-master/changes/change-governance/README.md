# Change: Governance

**Feature:** [Artifact master](../../README.md)
**From:** 2.0.0
**To:** 3.0.0
**Type:** Requirements

## Reason

The software team needs four governance rules for the artifact-driven change.
Phase 5 release work must move from the solution expert to a low-cost artifact
release expert. Phase 2 must follow a contract-first rule with feasibility
review by the implementation expert. Phases 1 and 2 must interview the user
with options and one recommendation when they see a better path. Phase 4 must
run tasks in parallel where the phase 3 dependencies permit it. Each rule adds
or changes a requirement, so the change bumps the major version.
