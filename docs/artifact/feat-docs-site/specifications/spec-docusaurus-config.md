# spec-docusaurus-config: Configure Docusaurus to render the docs tree

**Master:** [Specifications](README.md)
**Covers:** req-browsable-docs
**Context:** context-factory

## Description

The authored file `docusaurus.config.js` configures Docusaurus 3.9 to render the whole `docs/`
tree at the root of the website. The file is CommonJS. It reads the title, the URL, and the base
URL from `site.json`. It renders `.md` files as CommonMark, because three pages use indented code
blocks with `<name>` placeholders, which MDX rejects. It excludes the templates. A custom sidebar
generator gives each folder without a `README.md` a generated index page.

## Contract

### Settings

| Setting | Value | Reason |
| --- | --- | --- |
| `title` | `site.title` | The project sets the title through the option. |
| `url` | `site.url` | The project sets the origin through the option. |
| `baseUrl` | `site.baseUrl` | The project sets the path through the option. |
| `trailingSlash` | `true` | Each route ends with `/`, so a relative URL path such as `decisions/` resolves inside the current folder. See `adr-trailing-slash`. |
| `staticDirectories` | `[]` | The site has no static folder and no favicon. |
| `onBrokenLinks` | `'warn'` | A broken link does not stop the build. |
| `markdown.format` | `'detect'` | `.md` files render as CommonMark, `.mdx` files as MDX. |
| `markdown.hooks.onBrokenMarkdownLinks` | `'warn'` | A broken Markdown link does not stop the build. |
| `presets[0]` | `['classic', {...}]` | The classic preset gives the docs plugin and the theme. |
| `presets[0][1].blog` | `false` | No blog. |
| `presets[0][1].docs.path` | `'../../docs'` | The docs folder of the repository, relative to `apps/documentation/`. |
| `presets[0][1].docs.routeBasePath` | `'/'` | The docs are the website. `docs/README.md` is the home page. |
| `presets[0][1].docs.sidebarPath` | `'./sidebars.js'` | The one autogenerated sidebar. |
| `presets[0][1].docs.numberPrefixParser` | `false` | A number prefix in a file name stays in the route. |
| `presets[0][1].docs.exclude` | The list below | The Docusaurus defaults, plus the templates. |
| `presets[0][1].docs.sidebarItemsGenerator` | The function below | A generated index for each folder without a `README.md`. |
| `presets[0][1].theme.customCss` | `'./src/css/custom.css'` | The seed file of the project. |
| `themeConfig.navbar.title` | `site.title` | The navbar shows the site title. No navbar items. |

`site` is the result of `require('./site.json')`. The file reads no other source of settings.
The file does not set `favicon`.

### Reasons for CommonMark

These three pages use 4-space indented code blocks with `<name>` placeholders. MDX rejects
`<name>` as a JSX tag. CommonMark renders the block as code.

| Page | Lines |
| --- | --- |
| `docs/wiki/documentation/artifact-driven/README.md` | 8 to 30 |
| `docs/wiki/design/ddd/README.md` | about 138 to 146 |
| `docs/artifact/feat-ddd-design/specifications/spec-domain-templates.md` | about 15 to 23 |

### Exclude list

```js
exclude: [
  '**/_*.{js,jsx,ts,tsx,md,mdx}',
  '**/_*/**',
  '**/*.test.{js,jsx,ts,tsx}',
  '**/__tests__/**',
  '**/templates/**',
],
```

The first four entries are the Docusaurus defaults. A custom `exclude` replaces the defaults, so
the file restates them. The last entry removes the 19 files under
`docs/wiki/documentation/artifact-driven/templates/` and `docs/wiki/design/ddd/templates/`. They
contain bare `<name>` placeholders that break MDX and vanish in CommonMark. They are copy-mode
factory files, and no page links to them.

### Sidebar generator

```js
async function sidebarItemsGenerator({ defaultSidebarItemsGenerator, ...args }) {
  const items = await defaultSidebarItemsGenerator(args);
  return withIndexes(items, args.docs);
}
```

`withIndexes(items, docs)` walks the items recursively. For each item with `type === 'category'`:

| Case | Change |
| --- | --- |
| The category has a `link` with `type === 'doc'` | Set `label` to the `title` of the doc in `docs` whose `id` equals `link.id`. |
| The category has no `link` | Set `link` to `{ type: 'generated-index', slug: '/' + folder }`. `folder` is the `sourceDirName` of a direct doc child. When the category has no direct doc child, `folder` is the parent folder of the `folder` of its first child category. |
| Other | No change. |

An item that is not a category does not change. The order of the items does not change.

The reason: nine feature and change summaries under `docs/artifact/` link to a bare folder, `](decisions/)` or `](changes/)`, that
has no `README.md`. Without a link, the category has no page and the link gives a 404.

### README.md as index

Docusaurus treats `README.md` as the category index of its folder. The index doc gets the route
of the folder. With `routeBasePath: '/'` and `trailingSlash: true`, the routes are:

| File | Route |
| --- | --- |
| `docs/README.md` | `/` |
| `docs/artifact/README.md` | `/artifact/` |
| `docs/artifact/feat-x/README.md` | `/artifact/feat-x/` |
| `docs/artifact/feat-x/decisions/adr-y.md` | `/artifact/feat-x/decisions/adr-y/` |
| Generated index of `docs/artifact/feat-x/decisions/`, no `README.md` there | `/artifact/feat-x/decisions/` |

Each route is under `baseUrl`. With `base-url = "/repofactory/"`, the home page is
`/repofactory/` and `feat-x` is `/repofactory/artifact/feat-x/`.

### Trailing slash

`trailingSlash: true` adds a trailing `/` to each route. The build writes `<route>/index.html`, for
example `build/artifact/feat-x/index.html`. GitHub Pages serves `index.html` for a folder URL.
Docusaurus rewrites each link to a Markdown file path, for example `](decisions/adr-y.md)`, to the
route of that doc at build time. A link to a `README.md` opens the route of its folder. Docusaurus
does not rewrite a link to a URL path, for example `](decisions/)`; the browser resolves it against
the current route. From `/artifact/feat-x/`, the link `decisions/` resolves to
`/artifact/feat-x/decisions/`, which is the generated index of that folder. With
`trailingSlash: false`, the same link would resolve to `/artifact/decisions/`, which does not exist.

## Errors

`npm run build` fails when `site.json` is absent, because `require('./site.json')` throws.
`npm run build` fails when `src/css/custom.css` is absent.
`npm run build` prints a warning and continues when a link is broken, because both link hooks
are `'warn'`.
The check `configMatches` in `tests/eval.nix` fails if the file text does not match one of
the seven patterns of `spec-eval-checks`.
